# まちカルテ（仮）

> 本リポジトリは「Built with Claude: Japan 2026」（開発期間 2026-11-02 12:00 〜 11-08 20:00 JST）の参加作品です。

## 課題 — 誰の、どんな困りごとか

**都市計画基礎調査**では、建物の用途や階数といった基礎的な属性を、いまも**自治体職員が現地を歩いて確かめている**。
PLATEAU のような 3D 都市モデルがあっても、属性が欠けた建物は残り、更新は人手の現地踏査に頼っている。

新宿区（13104）の実データで見ると、**全 57,780 棟のうち 4,982 棟が、用途も階数も不明のまま**（用途コード 461＝不明、階数センチネル 9999 などが一致）。
これを全部そのまま現地で回るのは重い。**まちカルテは「どこを見に行けばよいか」を自動で 1/12 に絞り込み、推定を添え、人が地図で確認・確定して、自治体向けの更新候補リスト（CSV / GeoJSON）として出す。**

骨格：**抽出（自動）→ 推定（Claude）→ 確認・確定（人）→ 更新候補の出力（自動）**

設計の正本は [`docs/design.md`](docs/design.md)。

## デモを見る最短手順

> **前提：実データ（PLATEAU 等）の取得が必要です。** 権利の都合で生データはリポジトリに含めていません（`data/` は git 管理外）。

1. **依存を入れる**：`uv sync`（Python 3.12 + [uv](https://docs.astral.sh/uv/)）
2. **環境変数**：`cp .env.example .env` → `ANTHROPIC_API_KEY` を記入（Claude 機能を使う場合。地図・絞り込みだけなら無くても動く）
3. **データを置く**：[`data/README.md`](data/README.md) の「取得記録」に従い、PLATEAU 新宿区 2025/2023 年度版 CityGML・Overture Places・OSM POI を `data/raw/` 以下に配置
4. **取り込み**：`make ingest`（CityGML を DuckDB へ。不明群 4,982 棟を抽出）
5. **起動**：`make serve` → ブラウザで **http://localhost:8000/**（トップが絞り込みのデモ、`/survey.html` が現地調査）
6. （任意）`make eval` で評価レポート [`docs/results.md`](docs/results.md) を再生成／`make export` で更新候補リストを出力

**デモ動画**：（準備中 — 公開後にここへ URL を記載）

スマホ実機で見る場合は `make tunnel`（HTTPS トンネルを張って URL/QR を表示。現地調査の位置情報・カメラ・音声には HTTPS が必要）。

## テーマとの対応

**テーマ1「あなたにしかない深さを」。** 地域のデータが更新され続けない——という**構造的な問題**に正面から取り組んだ。
華やかな新機能ではなく、自治体の現地踏査という地味で重い実務を、**PLATEAU の実データ（新宿区 57,780 棟）**で具体的に小さくする。
件数・精度・費用はすべて実データから数え（[`docs/results.md`](docs/results.md)）、推測の数字は書かない。うまくいかなかったこと（用途推定で Claude が既存ベースラインを超えなかったこと）も正直に残している。

## デモの流れ

1. **57,780 → 4,982 の絞り込み**：トップで「新宿」と入れると全棟が現れ、抽出すると調査対象（不明群）だけが橙に浮かび上がる。件数は毎回データから数える。
2. **確認画面での確定**：1 棟ずつ、推定（用途・階数）と根拠・信頼度を見て、人が「そのまま確定／修正して確定」。公式データは上書きせず、推定は `candidates`、確定は `confirmations` に入れる。
3. **現地調査（スマホ）**：地図で対象を選び、近い順にグループで回る。**音声入力**でメモ、**現地写真は端末内で顔を自動ぼかし**、各棟・グループへ**徒歩経路（外部アプリ連携＋アプリ内 OSRM 経路）**で移動。
4. **出力**：人が確定した属性だけを、自治体向けの**更新候補リスト（CSV / GeoJSON）**と**調査レポート**として出す。判断不能・未確定は出さない。

## Claude の使いどころ

- **推定の根拠文**：用途・階数の推定に、なぜそう判断したかの文章と信頼度を付ける（`estimate/claude_infer.py`）。
- **判断不能の自己申告**：外観だけで決められない棟は、推測で埋めず「判断不能」を返させる（推測で埋めるのは誤答より悪い、という方針）。
- **現地確認が必要な区分の要約**：判断不能の棟を区分ごとにまとめ、「現地で何を見れば埋まるか」を Claude が要約（`api/onsite.py`、区分ごとに 1 回だけ）。
- **調査レポートの文章**：数字は SQL で出し、文章だけ Claude が書く（`export/report.py`、1 回の生成で 1 回だけ呼ぶ）。
- **音声メモの振り分けと聞き返し**：話したメモを用途コード・階数・特徴に構造化し、足りない項目を 1 つずつ聞き返す（`api/voice.py`）。
- **正直な不採用**：用途推定では、Claude の用途は高さ 20m 以上で近傍ベースライン（(c)）を超えなかったため、**用途は候補提示にとどめ、Claude での上積みは採用しなかった**（経緯と数字は [`docs/results.md`](docs/results.md)・[`docs/decisions.md`](docs/decisions.md)）。

費用はキャッシュ（入力ハッシュ）で二重課金を防ぎ、トークン・費用をログに残す。モデルは環境変数 `CLAUDE_MODEL` で切り替える。

## 評価（Phase 10）

数字は実測のみ。**`make eval` で [`docs/results.md`](docs/results.md) に再生成**する（件数・精度は毎回 DB から計算、Claude 検証・費用は課金を伴う一度きりの実測を `docs/decisions.md` から引く。各数字に出典を併記）。主な結果：

- **訪問が必要な棟：57,780 → 4,982（削減率 91.4%）**
- **階数の精度（不明群の高さ分布で重み付け）：完全一致 69.5% / ±1階 95.5%**
- **用途：近傍＋高さのベースライン（不明群重み 62.3%）を POI 結合も Claude も超えず → 用途は候補提示にとどめる**
- **Claude が根拠なく断定して外した件数：0（判断不能を安定して返す）**
- **現地確認が必要：521 棟（高さ欠損で階数が判断不能）**

詳細・最新値は [`docs/results.md`](docs/results.md)。

## セットアップ

Python 3.12 + [uv](https://docs.astral.sh/uv/) を使う。

```bash
uv sync                 # 依存をインストール（.venv を作成）
cp .env.example .env     # APIキー等を記入
```

主なターゲットは `Makefile` を参照（`ingest` / `serve` / `eval` / `export` / `test` / `tunnel`）。

## データの取得手順

生データと派生データは `data/` 以下に置く（git 管理外。配置の詳細は [`data/README.md`](data/README.md)）。

- **PLATEAU 新宿区（13104）CityGML** … 2025年度版を `$DATA_DIR/plateau/2025/`、版間差分用に 2023年度版を `$DATA_DIR/plateau/2023/`
- **POI** … Overture Maps Places と OpenStreetMap の新宿区範囲
- **オルソ** … 東京都区部オルソ（東京都デジタルツイン）の新宿区分

取得先・格納パスは `data/README.md` にまとめる。
