# web

MapLibre GL JS による地図と確認画面を置く場所。まずはビルド不要の素の HTML/JS で始める。
背景地図は国土地理院タイル（出典表示を必ず出す）。

- `index.html` … **配布時の最初のページ（紹介）**。このプロダクトでやること・課題・骨格（抽出→推定→確認→出力）を
  紹介し、「次のアクション」で建物データ画面（`/map.html`）へ送る。大見出しの件数は `/api/stats` から取る
  （API 未起動なら設計書の値を表示）。自己完結（スタイルは inline、外部アセットなし）。
- `map.html` … 建物データ画面（旧 `index.html`）。画面の骨組み（件数カウンタ・優先度リスト・属性パネル・帰属表示リンク）
  に、配布デモの段階UI（検索オーバーレイ・抽出ボタン・演出キャンバス）を重ねている。
- `app.js` … 地図（地理院 淡色＋`fill-extrusion`）、全棟⇄調査対象のみの切替アニメ、件数カウントダウン、
  リストから `flyTo`、クリックで属性パネル。API は `/api/*`、建物は `/data/buildings.geojson`。
  `body.demo` のときは数字と建物色を即時に出さず、`window.MK`（map / 色の切替 / カウント）を `demo.js` へ渡す。
- `demo.js` … 配布デモの進行役。段階0=街名を入力（「新宿」）→ 段階1=全棟を灰色で表示 →
  段階2=「調査必要箇所を抽出」でエレクトリックな演出（自前 Canvas）→ 調査対象が橙に浮かび、作業UIが現れる。
  件数は `/api/stats` から取り、直書きしない。
- `style.css` … レイアウト＋配布デモの段階表示（`body.demo` + `stage-0/1/2`）。MapLibre GL JS は CDN（unpkg）から
  読み込む（ビルド不要）。

- `survey.html` / `survey.js` … 現地調査モード（スマホ前提）。地図で対象を選ぶ→近い順/優先度順の
  プラン→1棟ずつ入力。入力画面には**音声入力（試験的）**がある。`?plan=<id>` を付けて開くと、
  PC で保存した**調査計画**を読み込んでその棟一覧が開く（下記）。スマホだけで選んで調査する流れも残す。
- `vendor/qrcode/` … 調査計画の受け渡し URL を QR 化するライブラリ（MIT, CDN 非依存。`vendor/qrcode/README.md`）。

## 調査計画の受け渡し（QR コード）

PC（`map.html`）で選んだ棟を**調査計画**としてサーバーに保存し、QR コードで現地スマホへ渡す。

- 選ぶ：地図を**ドラッグで囲む**（左上「⬚ 囲んで計画に追加」）と、囲んだ中の調査対象（3Dの橙の棟）が
  まとめて計画に入る。ほかに確認カードの「＋ 調査計画に追加」、現地確認パネルの各区分「＋ この区分を調査計画に追加」。
  **計画に入れた棟は地図で紫（`b-plan`）にハイライト**され、選択中が一目でわかる。
  左下の「📋 調査計画」トレイに溜まる（選択は現地調査モードと同じ `localStorage`＝ともに合流）。
- 保存：トレイの「QRで渡す」で `POST /api/plans` → 計画IDを受け取り、受け渡し URL
  （`<いまのオリジン>/survey.html?plan=<id>`）と **QR** を表示。URL はコピーもできる。
- 読み取り：スマホで QR を読むと、その計画の棟一覧（調査プラン）が開く。既存の現地調査がそのまま動く。
- グループ分け：**11棟以上**のときだけ 200m 圏でグループ化する。**10棟以下は1グループ**にまとめ、1本のルート（Google マップ、上限10地点）で全棟を順に回れる。
- 進捗：トレイの「進捗」で保存済み計画の **何棟中何棟終わったか**を見る（`GET /api/plans`）。進捗は
  `survey_plans` に状態を持たず、`confirmations` との突き合わせで都度数える（現地・机上どちらの確定でも「調査済」）。

## 共有（Web Share API）

更新候補のダウンロード（CSV / GeoJSON / レポート）の横に「共有」がある。`navigator.share` で
**CSV / GeoJSON のファイルそのもの**を共有する（メール・AirDrop・各アプリへ）。**対応端末でだけ**ボタンを出し、
非対応ならダウンロードのみ（ボタンは出さない）。`map.html`・`survey.html` の両方にある。

`api`（FastAPI）が `/` で配信するので、`make serve` 後に http://localhost:8000/ を開く（紹介ページ）。
建物データ画面は http://localhost:8000/map.html 、現地調査モードは http://localhost:8000/survey.html 。
（`/survey/` は現地写真の保存先 `data/survey/` のマウントなので、UI は `survey.html` を開く）

## 音声入力（試験的）について

現地調査の1棟入力に「🎤 音声で入力」がある。Web Speech API（`SpeechRecognition`）を使う。

- **音声は端末内では処理されない。** 認識はブラウザ提供元のサーバー（**Chrome→Google / Safari→Apple**）で
  行われる。まちカルテは**音声を保存せず、認識後の文字だけ**を扱う。初回に一度だけ同意を取り、了解した人だけが使う。
  自治体が導入を検討する際に判断できるよう、この制約を正直に記す（詳細は `docs/decisions.md`）。
- 対応：Android Chrome（実用的）、iOS Safari 14.5+（連続認識は不安定）。**Firefox は非対応**。
- 音声が非対応・拒否・失敗でも、**手入力がそのまま使え、入力は消えない**。対応端末でだけボタンが出る。
- 認識後のテキストは `POST /api/voice_parse` が Claude で用途・階数・特徴に振り分ける（読み取れない項目は空のまま）。

### 実機で試す手順

- **PC（localhost）**：HTTP でOK。http://localhost:8000/survey.html で音声まで動く。
- **スマホ実機**：マイクは secure context 必須のため、**同一Wi-Fi＋HTTP（IP直叩き）では音声は動かない**
  （地図・手入力は動く）。音声を試すには **HTTPS トンネル**が要る：
  ```
  cloudflared tunnel --url http://localhost:8000     # 表示される https URL をスマホで開く
  # または
  ngrok http 8000
  ```
  得られた `https://…/survey.html` をスマホのブラウザで開き、「音声で入力」→マイク許可で確認する。
